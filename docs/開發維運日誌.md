### bug + db · 研究者儀表板警示「確認」按鈕沒反應
- **症狀**：研究者/PI 按警示「確認」完全沒反應。
- **根因**：正式資料庫 `alerts` 表缺 `acknowledged_by` 欄位——補該欄位的 migration
  `20260326070000_alert_acknowledge_cols.sql` 因 migration 版本錯位（靠手動套用）**從未套進
  production**；前端 `acknowledgeAlert()` 寫入該欄位時 Postgres 回 `42703`，被前端 catch
  吞掉只留 `console.error`，畫面零回饋。
- **修法（正式資料庫變更）**：經 Management API 手動對 production：
  1. `ALTER TABLE alerts ADD COLUMN IF NOT EXISTS acknowledged_by TEXT;`（純新增欄位）
  2. 新增 `researcher_ack_alerts` UPDATE policy——原本 `alerts` 僅 `pi_manage_alerts`（限 pi）
     可寫，故新增讓 researcher 也能確認**自己主刀醫師病人**的警示（沿用現有 surgeon 範圍模型）。
- **影響**：**不需前端部署**；補完後 PI/researcher 於 App 內按「確認」即正常生效並寫入
  `audit_trail`。以 `id=-1` 空更新驗證 `42703` 已消除、未動任何真實資料。
- **附註**：本次亦確認 **production RLS 與磁碟 `base_schema` 不一致**（prod 的
  `researcher_read_alerts` 為 surgeon 綁定）——正式環境 RLS 須以 `pg_policies` 直接查詢為準，
  勿以磁碟 migration 為權威。
- **紀錄**：migration `prototype/supabase/migrations/20260726000000_researcher_ack_alerts.sql`；
  commit `84ea236`。
